# Propuesta de mejora estudiantil del repositorio

Este repositorio corresponde al sitio web de la asignatura **Teoría de Sistemas — Ingeniería Civil en Ambiente**.

La invitación es a revisar la plataforma desde la perspectiva de un/a estudiante y proponer mejoras en su experiencia de uso, diseño, navegación y organización visual.

## Forma de trabajo recomendada

1. Realiza un **fork** de este repositorio en tu cuenta de GitHub.
2. Clona tu fork en tu computador.
3. Instala las dependencias.
4. Ejecuta el sitio localmente.
5. Realiza tus cambios libremente en tu fork.
6. Registra los cambios mediante commits descriptivos.
7. Cuando tengas una propuesta suficientemente desarrollada, abre un **Pull Request** desde tu fork hacia la rama `main` del repositorio original.

## Ejecutar el sitio localmente

```bash
git clone https://github.com/TU-USUARIO/Repositorio-Teoria-de-Sistemas.git
cd Repositorio-Teoria-de-Sistemas
npm install
npm run dev
```

Luego abre en el navegador la dirección local que indique Astro, normalmente:

```text
http://localhost:4321/
```

## Qué puedes modificar

Puedes explorar y proponer cambios en:

- navegación;
- jerarquía visual;
- organización de contenidos;
- experiencia de usuario;
- páginas de clases;
- acceso a materiales;
- visualización en computador y teléfono;
- componentes y estructura general del sitio.

La idea es que desarrolles tu propia lectura crítica de la plataforma. No necesitas limitarte a cambios que el profesor haya sugerido previamente.

## Qué conviene preservar

- No modificar el contenido académico sustantivo sin identificar claramente el cambio.
- No eliminar enlaces institucionales o materiales del curso sin explicarlo.
- No incorporar datos personales de estudiantes.
- No subir credenciales, contraseñas, tokens ni archivos privados.
- Los documentos alojados externamente en Google Drive no necesitan copiarse al fork; el sitio utiliza enlaces hacia esos recursos.

## Al preparar el Pull Request

Incluye brevemente:

1. qué problema o dificultad observaste;
2. qué cambio implementaste;
3. por qué crees que mejora la experiencia;
4. capturas de pantalla, si ayudan a entender la propuesta.

No es necesario que el rediseño sea definitivo. El objetivo es disponer de una propuesta concreta que podamos revisar, discutir y mejorar en conjunto.
